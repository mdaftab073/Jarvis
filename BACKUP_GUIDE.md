# Backup Guide for Jarvis

## Overview
This guide explains how to create and manage backups of the Jarvis platform using the provided `scripts/backup.py` utility.

## What is Backed Up?
- **PostgreSQL database** – dumped via `pg_dump` in custom format.
- **Chroma vector store** – the persistent directory defined by `CHROMA_PERSISTENT_DIRECTORY` (default `chroma_db`).
- **Uploaded files** – all files stored under the `uploads/` directory.

## Running a Backup
```bash
# From the repository root
python backend/scripts/backup.py
```
The script will:
1. Create a timestamped directory under `backend/backups/` named `jarvis_backup_<YYYYMMDDTHHMMSSZ>`.
2. Dump the database to `postgres.dump`.
3. Copy the Chroma directory and uploads.
4. Archive the whole backup directory into a ZIP file and output its path.

## Backup Location
All backups are stored in `backend/backups/`. Keep this directory under version‑controlled storage **outside** of the repository or move the archives to a secure external storage (e.g., S3, NFS).

## Scheduling Automated Backups
You can schedule the backup script with a cron job on your host or a GitHub Action. Example cron entry (run daily at 02:00 UTC):
```cron
0 2 * * * cd /path/to/jarvis && python backend/scripts/backup.py >> /var/log/jarvis_backup.log 2>&1
```

## Restoring from a Backup
Use the companion `scripts/restore.py` script (see the Restore Guide).
